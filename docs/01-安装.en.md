# 01 · Installation and uninstallation

中文: `docs/01-安装.md`

## What you need

| Item | Requirement |
|---|---|
| Minecraft | 1.21.5 – 26.3 (two variants, see the mapping table in [04 · Compatibility and versions](04-兼容与版本.md)) |
| What to install | One zip: for 1.21.5–26.2 use [`../dist/doom.virtual.health-v3.1.0.zip`](../dist/doom.virtual.health-v3.1.0.zip); for 26.3 use [`../dist/doom.virtual.health-v3.1.0-mc26.3.zip`](../dist/doom.virtual.health-v3.1.0-mc26.3.zip) |
| Do I need experimental gameplay | No |
| Any prerequisites | None. Zero mods, zero external datapacks, zero resource packs |
| Single-player or server | Either; a server just has to accept datapacks (vanilla / Fabric / Paper all work) |

> The pack's two namespaces, `doom.virtual.health` (the core) and `doom.bossbar` (health bar integration), are in the same zip,
> so installing one installs both. Using the core without the health bar also works (just never call `doom.bossbar:*`).

## Installing (single-player world)

1. Download the zip matching your MC version (1.21.5–26.2 → `v3.1.0`; 26.3 → `v3.1.0-mc26.3`) and check the checksum first (see below);
2. Unzip → you get a folder `doom.virtual.health/`;
3. Put the whole thing into the world's `datapacks/`:

   ```
   .minecraft/saves/<your world>/datapacks/doom.virtual.health/pack.mcmeta   ← must be exactly this deep
   ```

   **One extra nesting level and it will not load** (e.g. `datapacks/doom.virtual.health/doom.virtual.health/` is wrong);
4. Go in-game (or `/reload` if you are already in).

## Installing (server)

1. Put the unzipped `doom.virtual.health/` into `<server root>/world/datapacks/` (for a multi-world server, the `datapacks/` of the relevant world);
2. `/reload` from the console, or restart the server;
3. The path is likewise `.../world/datapacks/doom.virtual.health/pack.mcmeta`.

> By the way: this pack does not touch vanilla house rules (it changes no `gamerule`, does not affect mob spawning, does not change the vanilla health cap),
> it only acts on entities it has "registered". So on a server with other datapacks it generally will not clash.

## How to confirm it installed

Do these three in order; getting any one of them right means it is running:

1. After `/reload` every player sees a red line in chat:

   ```
   [DVH] Virtual Health System Loaded.
   ```

   (from `doom.virtual.health:__load__`; `doom.bossbar:__load__` hooks in at the same time)
2. Type `/function doom.virtual.health:__help__` and chat prints a full page of the API list (visible to the executor only).
3. Summon a mob with virtual health and a health bar appears at its feet:

   ```
   /summon minecraft:zombie ~ ~ ~ {data:{dvh:{max_health:40d, health:40d, on_death:"say died"}}, NoAI:1b}
   ```

     The bar appearing = both the `auto_init` and `doom.bossbar` chains are working.

If the datapack failed to load, the load phase leaves lines like `Failed to load function ...` or
`Couldn't load ... as it's not a valid pack` in `logs/latest.log`. Searching for those two strings usually pins down which step went wrong.

## Uninstalling

1. First strip every virtual-health entity clean (deleting the pack outright leaves the system in an inconsistent state: entities still carry the
   `virtual_health_entity` tag and health bars are still hanging there):

   ```
   /function doom.virtual.health:__unload__
   ```

   It walks every `@e[tag=virtual_health_entity]`, calls `api/remove {with:{kill:false}}` (without killing the entity), and cleans up the health bars and scoreboards.

2. Delete `datapacks/doom.virtual.health/`;
3. `/reload`.

Whatever constant data is left in `storage doom.vh:ctx` / `doom.vh:const` / `doom.dbb:ctx` is harmless; to wipe it completely you can
`/data remove storage doom.vh:ctx ...` key by key, or just leave it alone — reinstalling overwrites it.

## Verifying your download

`../dist/SHA256SUMS.txt` holds the sha256 of each zip. Run this in the directory containing the zip:

```
Linux / macOS:        sha256sum -c SHA256SUMS.txt
Windows PowerShell:   (Get-FileHash .\doom.virtual.health-v3.1.0.zip -Algorithm SHA256).Hash
```

If it prints `OK` (or the hash equals the string in the list), the download is intact; if not, do not use it, download again.

## Troubleshooting order when it will not install

| Symptom | Check this first |
|---|---|
| No `[DVH] ... Loaded.` in chat | Is the path depth right (`datapacks/doom.virtual.health/pack.mcmeta`); did you `/reload` |
| The log says version mismatch / invalid pack | Is the game version below 1.21.6 (`pack_format` < 48); did you unzip, or did you drop the zip in directly (it must be unzipped) |
| No health bar at the mob's feet | Did the `doom.bossbar` namespace fail to load (reinstall the whole pack); is the `visible` selector hiding it from you |
| Hits deal no damage | Is that entity a virtual-health entity (`/tag <entity> list` to see whether `virtual_health_entity` is there); was it made invulnerable by `set_invulnerable {state:1b}` |
| Changed `vitality.json` and nothing happened | That file needs a **server restart**; `/reload` does not read it |
