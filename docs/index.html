Doom Virtual Health v3.0.0 — Minecraft 1.21.7 / 1.21.8

v3.0.0 1.21.6+ 纯原版 零依赖

为 Minecraft 实体注入独立于原版血量的虚拟血量系统，自动映射到 Bossbar。支持 auto_init（/summon 直接带 NBT）、高频 tick 伤害检测、自定义死亡回调、百分比血量判定、无敌控制、伤害倍率与余数精度补偿。

🤖 本项目由 Deepseek AI 协助开发与调试 — 代码审查、bug 修复、文档撰写均由 AI 辅助完成。当前为社区早期版本，亟待更多玩家测试，欢迎反馈：Issues

快速开始

方式一：auto_init（推荐）

/summon minecraft:zombie ~ ~ ~ {
  data:{dvh:{max_health:40d, health:40d, on_death:"say died"}},
  NoAI:1b
}

第一 tick 自动初始化，无需任何命令调用。

方式二：api/create

/execute as @n run \
  function doom.virtual.health:api/create {with:{max_health:21.5, health:20}}

绑定 Bossbar（可选）

/execute as @e[tag=virtual_health_entity] run \
  function doom.bossbar:api/create {with:{name:'"Boss"',color:red,style:progress,visible:"true",targets:"@a"}}

扣血 / 加血 / 无敌

# 扣 500 mHP（= 0.5 HP）
/execute as @e[tag=virtual_health_entity] run \
  function doom.virtual.health:api/add_health {points:-500}

# 无敌
/execute as @e[tag=virtual_health_entity] run \
  function doom.virtual.health:api/set_invulnerable {state:1b}

伤害与治疗机制

Health = 512f（原版探针）
→ 受到攻击 → Health 下降
→ Tick 采样: temp = Health × 2200，对比 baseline = 512 × 2200
→ delta = baseline − temp
→ delta × dvh.damage_mult / 2200 → mHP（×1000 标度）
→ dvh.health −= mHP，dvh.rem_damage += 余数（下次进位）
→ Health 复位 512f
→ dvh.health ≤ 0 → trigger_death

精度：0.001 HP（mHP）。余数补偿保证长期累计不丢失。

伤害倍率 dvh.damage_mult（默认 1000 = 100%）

倍率效果
20020% 伤害（等效原 Resistance IV）
50050% 伤害
1000100% 伤害（默认）
2000200% 伤害（易伤）

死亡回调 on_death

触发时机：dvh.health 降至 0（trigger_death）时执行。

用法：on_death 是任意命令字符串，以 VH 实体位置执行：

/execute as @e[tag=virtual_health_entity] run \
  function doom.virtual.health:api/create {with:{max_health:100, health:100, on_death:"say I died"}}

或 auto_init 时：

/summon minecraft:zombie ~ ~ ~ {
  data:{dvh:{max_health:100d, health:100d, on_death:"function mypack:boss_death"}},
  NoAI:1b
}

执行语义

  • 等价于 execute at @s run <on_death 命令>，@s 是 VH 实体
  • 不要写 @s[tag=virtual_health_entity]（选择器在回调时已失效），直接用 @s
  • 回调执行后实体被 out_of_world 伤害杀死
  • on_death 为空字符串视为无回调，直接进入死亡流程
  • 指定 on_death 时跳过 UUID 归属追踪；未指定则追踪 last_hurt_by_mob 生成击杀 credit

常见写法

# 广播死亡消息
on_death: "say A VH entity has died"

# 调用自定义处理函数
on_death: "function mypack:boss_killed"

# 播放音效（以实体位置）
on_death: "playsound minecraft:entity.wither.death master @a ~ ~ ~ 1 1"

# 生成掉落物
on_death: "summon minecraft:item ~ ~ ~ {Item:{id:\"minecraft:diamond\",Count:1b}}"

auto_init 自动初始化

/summon 时实体携带 data:{dvh:{...}}，第一 tick 自动完成 create + apply_trigger：

/summon minecraft:zombie ~ ~ ~ {
  data:{dvh:{max_health:"2000", health:"2000"}},
  NoAI:1b
}
  • 支持字段：max_health / health / on_death
  • 值可为数字（double）或字符串（如 "2000"，mcdoc 补全用）
  • 自动补全：Spyglass + mcdoc 插件在 data:{dvh:{ 处提示
  • auto_init 后自动执行 apply_trigger（分配 vitality 触发器）

vitality 附魔触发器

vitality 附魔挂在实体装备上，由附魔 tick 驱动装备加成同步，替代纯命令轮询。

  • 附魔文件：enchantment/vitality.json（槽位：saddle、mainhand）
  • Riding 实体（猪/马/驴/骡/骷髅马/僵尸马/骆驼/炽足兽）→ 主手槽
  • 非 Riding 实体 → 鞍槽
  • api/apply_trigger 自动分配，也可手动调用
  • tick effect 驱动 api/sync/equipment_bonus：扫描 8 槽 attribute_modifiers 同步到 dvh.max_health

注意：修改 enchantment JSON 需要重启服务器（/reload 无效）。

  1. 在 Releases 下载数据包 zip
  2. 放入存档的 datapacks/ 文件夹

已知 Edge Cases（边界情况）

亟待更多玩家测试：以下为代码审查中识别出的边界情况，部分已在设计中规避，部分受原版机制限制。

数值精度类

#场景表现规避
E1auto_init 的 NBT 用 double（40d）旧版宏展开 40.0 报错已修复为 data get 版（兼容 double/int/string）
E2get_percentage 血量 < 1 HP整数除法可能显示 0%低血量用 get_health_mhp 精确读取
E3scale 参数为 0除零报错scale:1（mHP）或 scale:1000（HP）
E4add_health 大量治疗钳制到 max_health已内置 #max_safe 溢出保护
E5damage_mult 过大数值溢出已内置上限 100000

机制限制类（原版限制）

#场景表现
E6单 tick 超大数据伤害（/damage 999999）Health 探针单次最多检测 512 HP，超出截断
E7治疗 Health 探针上限 1024单次最多补 512 HP
E8实体在未加载区块tick 检测暂停，血量不变
E9damage_mult 极小时向下取整后单次伤害可能为 0
E10kill 命令直接杀死（绕过 VH）on_death 不触发
E11原版 Regeneration/饱和回复Health 上升被识别为 VH 治疗
E12玩家实体支持，但死亡掉落为原版行为

使用注意类

#场景表现
E13on_death 命令含复杂引号/宏宏展开可能破坏引号嵌套
E14多实体同一 tick 死亡全局 storage 同步执行，无并发问题
E15remove 后立刻 create需等 1 tick（NBT 写入延迟）
E16bossbar name 传 JSON 数组嵌套引号可能失败，建议单 JSON 对象

注意事项

  • kill 参数默认 {kill:1b}，移除时会杀死实体；不想杀用 {kill:0b}
  • on_death 回调不要写 @s[tag=virtual_health_entity]（选择器已失效），直接用 @s
  • add_health {points:负数} 对无敌实体无效；set_health 不受无敌影响
  • Bossbar api/create 重复调用 return fail
  • scale:1 = mHP，scale:1000 = HP
  • 修改 enchantment JSON（vitality.json）需要重启服务器
  • 伤害倍率范围 [1, 100000]（×1000 标度）
