# 04 · 兼容与版本
English: `docs/04-兼容与版本.en.md`

## 1 · 这份包声明了什么

从 1.21.9 起 MC 收紧了数据包元数据规则：`pack.mcmeta` 必须声明 `min_format`/`max_format`，
还得和 `supported_formats` 逐值对得上，对不上整包拒收。1.21.5–1.21.8 不认这两个字段。
所以本包拆成两份变体。命令层逐字节相同，只有 `pack.mcmeta` 和 `enchantment/vitality.json` 不一样。

主用份 `v3.1.0`（1.21.5 – 26.2）：
```json
{
  "pack": {
    "pack_format": 71,
    "supported_formats": { "min_inclusive": 71, "max_inclusive": 107 },
    "min_format": [71, 0],
    "max_format": 107,
    "description": "§cDVH v3.0 §7+ §9DBB\n§7Scale 22, max_health up to 95325"
  }
}
```

26.3 变体 `v3.1.0-mc26.3`（仅 26.3，纯新式）：
```json
{
  "pack": {
    "min_format": [121, 0],
    "max_format": 121,
    "description": "§cDVH v3.0 §7+ §9DBB\n§7Scale 22, max_health up to 95325"
  }
}
```

- 下限为什么是 71：71 = 1.21.5 的 data pack format。包内代码用了 1.21.5 才引入的 `equipment:{}`，
  源包原先声明的 `min_inclusive: 48` 是错的 ✗。v3.1.0 收紧到 71，和真实能力对齐。
- 上限为什么是 107：107 = 26.2 的 data pack format。26.3 = 121，归 26.3 变体。
- 26.3 变体为什么删掉 `pack_format`/`supported_formats`：MC 实测会报
  `Pack key supported_formats is deprecated starting from pack format 82. Remove supported_formats from your pack.mcmeta.`
  ⇒ 声明范围触及 82+ 就会触发。纯 82+ 包只能留 `min_format`/`max_format`。
- 描述串里的 `DVH v3.0` 和 `DBB`（Doom Bossbar）是包内显示名，按惯例保留原始写法。
  发行版号以本仓库 Release 标签为准，当前是 `v3.1.0`。两者指的是同一个版本。

要不要开实验性玩法：不用。包里只用了稳定的数据包能力：函数宏、实体自定义数据、Bossbar、附魔 JSON。

## 3 · 升级 / 降级

### 升级（例如以后出 v3.0.1）

1. 记下当前正在用的版本（`dist/` 里的 zip 文件名）；
2. 跑 `/function doom.virtual.health:__unload__` 先摘干净，免得实体上残留旧标签或血条；
3. 删掉旧目录，放入新的 `doom.virtual.health/`，跑 `/reload`；
4. 想让世界里的老怪重新获得虚拟血量：对它们重新跑 `auto_init`（`/data modify entity … data.dvh …`），或者 `api/create`。

### 降级

包内没有“数据迁移”这一步，降级步骤和升级一样：摘干净 → 换目录 → `/reload`。
降级可能让新版才有的字段被忽略，比如新加的 `on_death` 语义变化。先备份存档。

### 改哪些文件要重启服务器

| 改动 | `/reload` 够不够 |
|---|---|
| `function/**/*.mcfunction` | ✅ `/reload` 就够 |
| `tags/function/*.json`（含 `#minecraft:load` / `#minecraft:tick`） | ✅ `/reload` 就够 |
| `enchantment/vitality.json` | ❌ **必须重启服务器**（附魔注册只在启动时读）。26.3 上用错变体就是在这里炸的 |
| `pack.mcmeta` | 需要重新加载数据包（单人重进世界 / 服务器 `/reload` 后若没生效就重启） |

## 4 · 版本号规则（本仓库自 v3.0.0 起采用）

```
v<MAJOR>.<MINOR>.<PATCH>              正式版       例：v3.0.0
v<MAJOR>.<MINOR>.<PATCH>-beta.<N>     预发布       例：v3.1.0-beta.1
v<MAJOR>.<MINOR>.<PATCH>-rc.<N>       候选（可选） 例：v3.1.0-rc.1
```

| 位数 | 什么时候升 |
|---|---|
| **MAJOR** | 玩家或整合包作者必须动手才能继续用（storage 字段改名、函数路径改名、包结构变化、要开不同的实验性开关），或者换 Minecraft 大版本后的首次适配 |
| **MINOR** | 向后兼容的新能力、新内容：新增可自定义字段、新增 API、新增预设 |
| **PATCH** | 修 bug、性能、文档，以及不改行为的重打包（清幽灵文件、重算 sha256、修正包内描述、工程整理） |

Minecraft 版本不进版本号：它只写在 `pack.mcmeta` 和本文第 1~2 节，附件名里也不带。
这样换 MC 版本时，不用把历史附件全部改名。

Release 边界：产物（包体或 zip）任何一字节变了，就必须升 PATCH 并重发附件。只有文档或元数据变化才可以直接提交，不发版。
一个版本号只对应一份产物，永不复用；已发布的标签不移动、不删除。

## 5 · 已知的“改不动”的部分

这些是原版机制决定的，不是 bug（完整清单见仓库根 README 的 Edge Cases 节）：

- 单 tick 内超过 512 HP 的一次性伤害会被探针截断（E6）；
- 单 tick 内超过 512 HP 的一次性治疗会丢（E7）；
- 未加载区块里的实体不参与 tick 检测，血量不会变（E8）；
- `/kill` 直接杀死的实体不会触发 `on_death`（E10）；
- 玩家实体支持虚拟血量，但死亡掉经验或背包是原版行为，本包管不到（E12）。
