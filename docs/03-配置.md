# 03 · 配置：NBT · storage · 计分板 · 标签 · mcdoc
English: `docs/03-配置.en.md`

这一页给“要接自己的数据包 / 要写脚本生成怪”的人看。纯玩不用读。

## 1 · 实体 NBT（`auto_init` 的入口）

`/summon` 或 `data modify entity` 写进自定义数据 `data.dvh`，第一 tick 自动读取：

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `max_health` | double / string | ✅ | 最大虚拟血量，**HP 单位**（支持 `40d`、`40`、`"40"`） |
| `health` | double / string | ✅ | 初始血量，HP 单位（可以 ≠ `max_health`，用来做“已受伤的怪”） |
| `on_death` | string | — | 死亡回调命令串（不带前导 `/`） |

```
/summon minecraft:zombie ~ ~ ~ {data:{dvh:{max_health:40d, health:40d, on_death:"say died"}}, NoAI:1b}
```

写 `data.dvh` 之后，别在同一 tick 又手动调 `api/create`。`auto_init` 会替你调，重复调会 `return fail`。

## 2 · storage 布局

### `doom.vh:ctx` · 运行时数据（核心）

键名是单层扁平的，不是嵌套对象。这样是为了配合宏展开和 `data get` 的写法：

| 键 | 谁写的 | 说明 |
|---|---|---|
| `with` | `api/*` | API 入参转发槽：`{max_health, health, on_death?}` |
| `uid0` … `uid3` | `trigger_death` | 击杀归属用：`last_hurt_by_mob` 的 UUID 四个 int |
| `uid_hex` | `internal/uuid_join` | 上面四个 int 拼出来的 hex 字符串（给 `damage ... by <uuid>`） |
| `on_death` | `trigger_death` | 本次死亡要跑的回调命令串 |
| `state` | `api/set_invulnerable` | `0` = 可受伤，`1` = 无敌 |
| `_` | `api/*` | 宏参数暂存槽（键名是裸下划线，mcdoc 里必须写成 `"_"`） |
| `trigger` | `api/apply_trigger` | 装备 NBT 往返中转：读 `equipment.mainhand`/`saddle` → 改写 → 写回 → `data remove` |
| `b0` … `bf` | `internal/uuid_hex` | UUID 拆字节用（16 个槽） |
| `h0` … `hf` | `internal/uuid_hex` | 上面那 16 个字节的两位十六进制字符（拼 `uid_hex` 用） |

### `doom.vh:const` · 只读常量

| 键 | 说明 |
|---|---|
| `hex_chars` | 256 个两位十六进制字符串（`"00"` … `"ff"`）的查表数组，UUID→hex 转换用 |

### `doom.dbb:ctx` · 血条（`doom.bossbar`）运行时数据

| 键 | 说明 |
|---|---|
| `id` | 血条标识串（创建 / 同步 / 删除时认人用） |
| 其它 | 宏参数暂存（与核心同样的 `_` 套路） |

> 三份 storage 都是全局共享的临时工作区。同一 tick 内串行执行，所以安全。
> 但别在别的数据包里复用这些键，你写进去的值随时会被下一次 API 调用覆盖。

## 3 · 计分板清单

`__load__` 会把这些 objectives 建好（都是 `dummy`）：

| 计分板 | 类型 | 说明 |
| ----- | --- | ---- |
| `dvh.health` | 实体 | 当前虚拟血量 (mHP) |
| `dvh.max_health` | 实体 | 最大虚拟血量 (mHP) |
| `dvh.total_damage` | 实体 | 累计受伤 (mHP) |
| `dvh.total_healing` | 实体 | 累计治疗 (mHP) |
| `dvh.player_damage` | 实体 | 玩家造成的伤害 (mHP) |
| `dvh.rem_damage` | 实体 | 伤害余数（进位补偿） |
| `dvh.rem_heal` | 实体 | 治疗余数 |
| `dvh.pp` | 实体 | 百分比阈值（下界）`[0,100]`，你设它来划段 |
| `dvh.pp_max` | 实体 | 百分比阈值（上界）`[0,100]` |
| `dvh.prev_hp` | 实体 | 上一 tick 的血量探针值（×2200） |
| `dvh.damage_mult` | 实体 | 伤害倍率（×1000，默认 `1000` = 100%） |
| `dvh.saddle_bonus` | 实体 | 装备加成缓存 |
| `dvh.temp` | `#虚拟` | 内部临时计算 |
| `dbb.temp` | `#虚拟` | 血条内部临时标识 |

改这些值的时候注意：`dvh.health` / `dvh.max_health` **直接写计分板不会同步到系统内部**（内部以 storage/属性为准），
要用 `api/set_health` / `api/set_max_health` 这类 API。
`dvh.pp` / `dvh.pp_max` / `dvh.damage_mult` 正好相反，就是给你直接写的（`damage_mult` 也可以走 `api/set_damage_mult`）。

## 4 · 标签

| 标签 | 在谁身上 | 说明 |
| ---- | ---- | ---- |
| `virtual_health_entity` | 实体 | 虚拟血量实体标识，所有选择器都靠它 |
| `dvh.invulnerable` | 实体 | 无敌状态标记（`set_invulnerable {state:1b}` 加、`{state:0b}` 去） |
| `dbb.has_bossbar` | 实体 | 已绑定血条（`doom.bossbar` 用） |

实体类型标签：`#doom.virtual.health:riding`（猪 / 马 / 驴 / 骡 / 骷髅马 / 僵尸马 / 骆驼 / 炽足兽）。
`api/apply_trigger` 用它决定 vitality 附魔挂主手还是鞍槽。

函数标签（`#doom.virtual.health:<名字>`，供别的数据包用 `function #...` 调用，不必记 mcfunction 路径）：
`add_health` · `add_health_pct` · `add_max_health` · `add_max_health_pct` · `get_health` · `get_health_mhp` ·
`get_max_health` · `get_max_health_mhp` · `get_percentage` · `get_player_damage` · `get_total_damage` · `get_total_healing` ·
`load` · `remove` · `set_health` · `set_health_pct` · `set_invulnerable` · `set_max_health` · `tick`。

加载钩子接在 `#minecraft:load` / `#minecraft:tick` 上，装包即挂：

```
# load → doom.virtual.health:__load__ + doom.bossbar:__load__
# tick → doom.virtual.health:core/main + doom.bossbar:core/main
```

## 5 · mcdoc 补全（可选，编辑器里用）

包里有 3 个 mcdoc 文件：

| 文件 | 补全对象 |
| ---- | ---- |
| `mcdoc/doom.virtual.health.mcdoc` | `data modify storage doom.vh:ctx ...`，显式声明了上面表里每一个槽位，写错键名当场报警 |
| `mcdoc/doom.bossbar.mcdoc` | `data modify storage doom.dbb:ctx ...` |
| `mcdoc/doom.virtual.health.tags.mcdoc` | 函数标签参考 |

怎么用：VS Code 装 Spyglass 扩展 + `Misodee.vscode-mcdoc`，把整个 `doom.virtual.health/` 目录当工作区打开，
写 `data modify storage doom.vh:ctx ` 就会看到键名提示；写 `data:{dvh:{` 也会提示 `max_health` / `health` / `on_death`。
示例写在包内 `function/mcdoc.mcfunction`，可以照着抄。

> 新增运行时键时记得同步 mcdoc，否则编辑器会把这个键标成“未知键”（运行时不受影响）。

## 6 · 性能与写入频率（自己接包时要知道的）

- `core/main` 挂在 `#minecraft:tick` 上，每 tick 只对 `@e[tag=virtual_health_entity]` 工作，没注册的实体零开销；
- 每只实体每 tick 一次 `execute store result` 采样 + 一次 `scoreboard` 比对，是常数级；
- `doom.bossbar:core/main` 同理，只处理 `dbb.has_bossbar` 的实体；
- 想少花点开销：`on_death` 留空的怪少一段 UUID 追踪（追踪只在需要击杀归属时走）。
