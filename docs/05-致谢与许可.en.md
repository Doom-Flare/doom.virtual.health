## AI-collaboration stance

Code review, bug fixes and documentation for this project had Deepseek AI involved throughout (the early README said so at the top; that stance is kept here):

- The fixes from the v3.0 round — the "unified merge", the ceiling guard (H7), `auto_init`'s handling of doubles (E1) — came out of human–machine troubleshooting;
- The documentation (README, the `docs/` handbook, in-pack comments and mcdoc descriptions) has AI drafts and human confirmation in it;
- AI does not change where responsibility lies: every command in the pack is readable line by line in the repo ([`../doom.virtual.health/`](../doom.virtual.health)),
  so if something goes wrong, report it in [Issues](https://github.com/DoomDecapitator/doom.virtual.health/issues) — the author is responsible.

## Third-party boundaries (there is nothing of anyone else's in this repo)

- No third-party code, no third-party assets: every `mcfunction`, `enchantment/vitality.json` and mcdoc file in the pack is written by this project;
  the repo pulls in no external datapacks, models, textures, sound effects or font files.
- Icons/badges: the badges at the top of the README are dynamic image links to shields.io (not stored on disk, not committed to the repo);
  there are no binary image assets in the repo (`docs/` contains only the handbook and the documentation-site HTML).
- Documentation site: `docs/index.html` is a static page written by this project, with inline styles, referencing no CDN scripts or fonts.
- Minecraft itself: the vanilla IDs referenced in the pack (`minecraft:zombie`, `minecraft:entity.wither.death` and so on) are Mojang's content;
  this pack merely calls them and redistributes no Minecraft assets. Using this pack still requires complying with Minecraft's end-user licence agreement.
- No "no commercial use" style add-on terms: this repo uses standard MIT, with no additional all rights reserved clause or any similar third-party licence marker stacked on top.
